# Varmlen 0.2.0 Security Architecture

## Scope

Varmlen 0.2.0 closes the complete Linux and Android audit before further UI work.
The release covers privilege separation, DNS and reconnect leak prevention,
split-tunnelling correctness, Android VPN lifecycle, native packaging, secret
storage, updater integrity, SSRF protection, dependency updates, state-machine
races, reproducible builds, and release verification.

The frontend redesign and a Linux CLI are separate follow-up projects. The
daemon protocol introduced here must be suitable for a future CLI without
making the CLI part of the 0.2.0 release.

## Linux architecture

### Privilege separation

Replace the user-owned file-capability helper with a root-owned `varmlend`
daemon installed under `/usr/libexec/varmlen`. No executable in a user-writable
directory receives Linux capabilities.

`varmlend` owns:

- Xray and TUN lifecycle;
- routes and policy routing;
- nftables rules;
- DNS interception;
- cgroup/BPF split tunnelling;
- persistent recovery state;
- post-crash reconciliation.

The GUI communicates through a root-owned Unix socket. The daemon authenticates
the peer with Unix peer credentials and authorizes only the active local user.
Requests and responses use a versioned protocol with operation IDs. This
protocol will later support a non-root Linux CLI.

The daemon has no hard dependency on systemd. Packages may include adapters for
systemd, OpenRC, runit, and s6. When no supported service manager is available,
the GUI may start the installed daemon through a fixed polkit action once after
boot. Connecting and reconnecting must not require repeated authentication.

### Connection state machine

The daemon is the sole owner of connection state:

`Disconnected -> Preparing -> Connected -> Blocking/Reconnecting -> Disconnected`

Before destroying a working tunnel, reconnect installs and verifies an atomic
hold-block. If that fails, the old tunnel remains active and reconnect fails.
No route, DNS, process, BPF, or nftables error may be silently ignored.

Cleanup verifies postconditions and reports `recovery_required` when state
remains. At startup, the daemon reconciles persisted process identity, TUN
devices, routes, nftables, DNS rules, and BPF attachments before accepting a
new connection.

### Portable DNS protection

DNS safety must not depend on systemd-resolved:

- Varmlen runs a local DNS inbound whose upstream is forced through the tunnel.
- nftables redirects system TCP and UDP port 53 traffic to that inbound.
- Direct port 53 traffic to physical and LAN interfaces is blocked, including
  when LAN access is enabled and for split-excluded applications.
- Direct DoT on port 853 is blocked unless an explicit future policy supports it.
- Application DoH remains ordinary HTTPS and follows that application's route.
- resolved, resolvconf, and openresolv integrations are optional adapters for
  correct system state reporting, not the security boundary.

Failure to establish or verify interception is a connection failure. Varmlen
must never rewrite `/etc/resolv.conf` destructively.

### Split tunnelling

Per-application exclusions must work for TCP and UDP and must survive:

- applications started before and after VPN connection;
- child and launcher processes, including Steam games;
- process replacement and executable relaunch;
- Flatpak applications such as Sober;
- reconnect, location change, VPN shutdown, and daemon recovery.

The daemon reports whether BPF/cgroup enforcement is active. It may not present
an exclusion as active when only a degraded fallback is running. Cgroup paths
are derived internally and resolved beneath a fixed cgroup root without
user-supplied traversal components or symlink following.

Automated integration tests use TCP and UDP echo/IP endpoints and process trees.
Live release verification uses `leakcheck`, an excluded native binary, an
excluded Steam game where available, and Flatpak/Sober where installed.

## Android architecture

### Native packaging

Android release tasks build `libxray.so` and `libhev-socks5-tunnel.so` for every
declared ABI before packaging. Missing libraries, unexpected Linux assets, ABI
mismatches, or unverifiable native inputs fail the build.

Xray and hev sources are pinned to immutable versions and verified with
repository-owned checksums. Release APK/AAB contents are inspected in CI.

### Honest VPN lifecycle

`connect()` completes only after:

- VPN permission is available;
- foreground service startup succeeds;
- TUN establishment succeeds;
- Xray starts successfully;
- tun2socks starts successfully;
- process and descriptor health checks pass.

Service errors return through a callback/state channel with an operation ID and
machine-readable error. Old operation results cannot overwrite newer state.

Android's real kill switch is system Always-on VPN with "Block connections
without VPN". Varmlen must not claim to implement a private equivalent. The UI
shows actual protection state where detectable and links to system VPN settings.

### Android split tunnelling

Allowlist and denylist modes are mutually exclusive. An empty allowlist is a
validation error and never becomes a device-wide VPN. Unknown or uninstalled
packages produce visible configuration errors instead of being silently ignored.
Instrumentation tests cover allow/deny modes with empty and populated lists,
TCP and UDP traffic, app restarts, and reconnect.

### Android secrets and lifecycle hardening

Long-lived subscription credentials use Android Keystore-backed storage.
Runtime Xray configuration is private and removed when no longer required.
Auto Backup and device transfer exclude VPN secrets, WebView storage, runtime
configuration, and logs.

Foreground-service failure is fatal to connection. Logs are redacted and
rotated. Release builds fail closed when signing configuration is missing and
verify the expected certificate digest after assembly.

## Shared security and reliability

### Shared source

Move duplicated Rust modules and frontend state stores into shared workspace
packages. Platform-specific VPN implementations remain adapters behind explicit
interfaces. CI checks that no security-sensitive copied implementation drifts.

### Subscription requests and SSRF

Resolve every initial and redirected hostname, reject private, loopback,
link-local, multicast, reserved, CGNAT, and metadata destinations, and connect
only to the checked address. Redirects are handled manually and checked per hop.
Response limits remain enforced while streaming.

### Core updater

Executable downloads require an independently trusted digest or signature.
Missing verification metadata is an error. Archives have compressed and
uncompressed size limits, extract into exclusive temporary files, are verified,
synced, and atomically installed. Install, activate, and remove operations are
serialized.

### WebView and asynchronous state

Untrusted support URLs pass through one HTTPS-only opener. Remove
`script-src 'unsafe-inline'` and reduce Tauri opener/IPC permissions.

Connect, disconnect, reconnect, polling, and subscription refresh use monotonic
operation generations or cancellation. A stale response cannot publish state.

## Testing

Behavior changes follow red-green-refactor. Required regression coverage:

- helper path traversal, symlink, and privilege-boundary tests;
- reconnect hold-block failure and old-tunnel preservation;
- daemon crash/startup reconciliation;
- DNS TCP/UDP interception, LAN denial, adapter failure, and fail-closed startup;
- split exclusions over TCP and UDP for existing/new/child/Flatpak processes;
- Android native asset and signing checks;
- Android connection acknowledgement and service failure propagation;
- Android empty allowlist and package-validation tests;
- SSRF DNS, redirect, rebinding-resistant connection, and address-range tests;
- updater missing/wrong digest, ZIP bomb, interruption, and concurrent install;
- frontend stale-operation tests.

Unit tests are supplemented by Linux network-namespace integration tests,
Android instrumentation tests, APK/AAB inspection, and live-machine leak checks.

## Build and release

Version 0.2.0 pins Rust, Node, JDK, Android SDK/NDK, Xray, and hev versions.
Release commands use locked dependency resolution and produce SBOM/provenance
where supported.

The release gate requires:

- Rust, frontend, helper, integration, and Android instrumentation tests;
- clippy and frontend checks without warnings treated as errors;
- npm and RustSec audits with no known exploitable vulnerabilities;
- DEB, RPM, AppImage, APK, and AAB builds;
- package-content, native-library, capability, and signing verification;
- live Linux DNS, reconnect, killswitch, TCP split, and UDP split checks;
- Android connection, split, and Always-on/lockdown verification on a device.

Only after the gate passes are commits pushed, tag `v0.2.0` created, and a
GitHub release published. Release notes describe the Linux daemon migration and
the Android system-lockdown requirement.

## Explicitly deferred

- visual/frontend redesign;
- Linux CLI implementation;
- interception or decryption of third-party DoH;
- support for additional platforms.

The future CLI will consume the same authenticated, versioned daemon protocol
and expose status, connect, disconnect, location selection, diagnostics, and
split-tunnelling inspection without duplicating networking logic.
